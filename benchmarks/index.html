Rigorous, transparent, and reproducible benchmarks measuring render latency, heap allocations, and concurrency limits across the Go ecosystem.

Rendering a typical web page containing a master layout, navbar, a 50-row data table with loops, badge conditionals, and text transformations:

* Hardware: AMD Ryzen 9 7950X, Linux 6.8, Go 1.22.6. Benchmarks run with go test -bench=. -benchmem.

How RHUI Achieves Near-Zero Heap Allocations

While standard html/template relies heavily on runtime reflection and repeated bytes.Buffer creations that burden Go's garbage collector, RHUI implements an internal buffer recycling engine:

Pre-compiled AST Caching

Components and page templates are lexed and parsed once into immutable AST trees. Re-rendering only walks the pre-computed tree without reparsing HTML tags.

sync.Pool Buffer Recycler

Every rendering worker borrows a pre-allocated bytes.Buffer from a concurrent pool and returns it reset. Under high throughput, memory allocations drop to virtually zero.
