Real-World SaaS Dashboard Showcase

How to build a feature-rich, responsive SaaS Analytics Dashboard in Go with sub-millisecond render times, live order feeds, and zero custom Go UI concatenation.

The Challenge: Can Go Build Complex Dashboards Cleanly?

When developers build complex server-rendered dashboards in Go, they typically suffer from two extremes:

The "Raw html/template" Pitfall

No component encapsulation. You end up with dozens of {{ template "part" . }} files, clumsy dot-context scoping ($.RootContext), and zero slot projections.

The "Heavy SPA" Pitfall

Pulling React, Next.js, or Vite requires dual-stack maintenance, complex REST/GraphQL APIs, Node build dependencies, and massive client JavaScript bundles for simple dashboards.

With RHUI, you get full component modularity (<ui:StatsCard>, <ui:DataTable>, <ui:Modal>) directly on the server, paired with HTMX and SSE for 100% reactive client interactivity.

Master Dashboard Layout (views/layouts/dashboard.rhui)

The master layout defines the responsive sidebar, sticky navigation, and content zone via the default <slot />:

views/layouts/dashboard.rhui 
<component name="DashboardLayout">
  <props title="SaaS Portal" activePage="overview" />

  <div class="min-h-screen flex bg-slate-950 text-slate-200">
    <<!-- Collapsible Sidebar -->
    <aside class="w-64 border-r border-slate-800 bg-slate-900/60 p-6 flex flex-col justify-between">
      <div>
        <h1 class="text-lg font-bold text-white flex items-center gap-2">
          <span class="w-3 h-3 rounded-full bg-brand-500"></span>
          {{ title }}
        </h1>
        <nav class="mt-8 space-y-1">
          <a href="/dashboard" class="block px-3 py-2 rounded-lg {{ activePage == 'overview' ? 'bg-brand-500/20 text-brand-300 font-semibold' : 'text-slate-400' }}">Overview</a>
          <a href="/customers" class="block px-3 py-2 rounded-lg {{ activePage == 'customers' ? 'bg-brand-500/20 text-brand-300 font-semibold' : 'text-slate-400' }}">Customers</a>
          <a href="/settings" class="block px-3 py-2 rounded-lg {{ activePage == 'settings' ? 'bg-brand-500/20 text-brand-300 font-semibold' : 'text-slate-400' }}">Settings</a>
        </nav>
      </div>
    </aside>

    <<!-- Main Application Content -->
    <main class="flex-1 p-8 space-y-6">
      <slot />
    </main>
  </div>
</component>

Reusable <ui:StatsCard> Component

Encapsulates metric presentation with conditional trend tags and formatted pipe filters:

views/components/StatsCard.rhui 
<component name="StatsCard">
  <props title="" value="" trend="" isUp="true" />

  <div class="p-5 rounded-2xl bg-slate-900 border border-slate-800 shadow-lg">
    <span class="text-xs font-semibold uppercase tracking-wider text-slate-400">{{ title }}</span>
    <div class="text-2xl font-black text-white mt-1">{{ value }}</div>

    <if condition=trend != ''>
      <div class="text-xs mt-2 font-medium {{ isUp == 'true' ? 'text-emerald-400' : 'text-rose-400' }}">
        {{ trend }}
      </div>
    </if>
  </div>
</component>

Zero Go UI Boilerplate in Backend Handlers

Notice how the Go backend only handles query execution and business logic, without touching HTML strings or component hierarchies:

main.go 
func handleDashboard(w http.ResponseWriter, r *http.Request) {
    // Fetch business data purely in Go
    metrics := getCompanyMetrics()
    customers := getRecentCustomers()

    // Render directly without HTML string concatenation
    engine.Render(w, "pages/dashboard.rhui", map[string]any{
        "Metrics":   metrics,
        "Customers": customers,
    })
}
