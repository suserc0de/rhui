RHUI CLI Tooling

Official lightweight Command Line Interface (CLI) to lint, validate, and format .rhui template files across your Go projects without external dependencies.

1 Overview

Similar to standard Go tools (go vet and gofmt), RHUI provides an official CLI tool located at github.com/suserc0de/rhui/cmd/rhui. It allows engineering teams to catch unclosed tags and syntax errors early in CI before deploying to production.

2 Installation & Usage

You can install the rhui binary directly using standard Go:

go install github.com/suserc0de/rhui/cmd/rhui@latest

Or run it directly from your project repository without installation:

go run github.com/suserc0de/rhui/cmd/rhui -h

3 Template Validation (rhui check / lint)

The check command scans directories recursively, verifying that all .rhui files contain valid AST structures, closed component tags, properly matched conditionals (<if></if><else></else>), and correct expression tokens.

# Check all templates in the current directory
rhui check .
# Check a specific templates directory
rhui check ./views ./templates
Success Output:
Validation passed: 12 .rhui file(s) checked successfully with zero errors.

4 Canonical Formatter (rhui fmt)

The fmt command formats and normalizes indentation (2-spaces) across templates, aligning tags, components, props, slot projections, and interpolation braces canonically:

Format In-Place (-w)

Directly overwrites and formats files:

rhui fmt -w ./templates
Dry-Run Mode (-d)

Exits with code 1 if unformatted files are found:

rhui fmt -d ./templates

5 CI/CD & GitHub Actions Workflow

Add rhui check to your automated testing pipeline to ensure no broken templates ever reach your main branch: 

name: CI
on: [push, pull_request]

jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: '1.26'

      # Validate RHUI templates before building
      - name: Validate RHUI Templates
        run: go run github.com/suserc0de/rhui/cmd/rhui check ./templates
