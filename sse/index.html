Realtime SSE Streaming & Live Components

Push live server-rendered HTML component diffs directly to client browsers over standard HTTP/2 Server-Sent Events with automated keep-alives and HTMX compatibility.

Why Server-Sent Events (SSE)?

Traditional Single Page Applications (SPAs) rely on WebSockets for real-time reactivity, requiring separate connection handshakes, stateful connection brokers, and client-side JSON reconciliation.

RHUI + SSE Advantages
  • Built-in automatic reconnection handled by browsers.
  • Traverses corporate proxies and firewalls without custom protocols.
  • HTTP/2 multiplexing allows hundreds of streams on one TCP link.
  • Renders directly via RHUI's zero-alloc component buffer pool.
WebSocket Pitfalls
  • Complex ping/pong heartbeats and custom reconnect loops.
  • Often blocked by aggressive corporate network firewalls.
  • Requires sending JSON payloads that must be parsed on clients.
  • Heavy JavaScript bundles and hydration overhead.

Creating the SSE Broker

RHUI provides a production-ready, concurrent SSE broker in github.com/suserc0de/rhui/sse that manages subscriber lifecycles, non-blocking broadcasts, and heartbeat pings.

main.go 
package main

import (
    "net/http"
    "github.com/suserc0de/rhui"
    "github.com/suserc0de/rhui/sse"
)

func main() {
    engine := rhui.NewEngine(rhui.EngineOptions{
        ViewsDir: "./views",
    })

    // Initialize SSE broker
    broker := sse.NewBroker(engine)

    // Stream endpoint
    http.HandleFunc("/events", broker.Connect)

    http.ListenAndServe(":8080", nil)
}

BroadcastComponent API

To send an updated component to all connected clients, call broker.BroadcastComponent(). RHUI compiles the template fragment, renders it with provided data, and sends the payload with the designated event name.

handler.go 
// Push a notification component update to all clients listening on "NewNotification"
err := broker.BroadcastComponent(
    "NewNotification",       // Event name
    "components/Notification", // Component path
    map[string]any{
        "Title":   "Order #1042 Paid",
        "Message": "Total: Rp 350.000 via QRIS",
        "Status":  "success",
    },
)
if err != nil {
    log.Printf("Failed to broadcast component: %v", err)
}

HTMX Client Integration

With HTMX and the sse extension, your frontend listens for backend events and swaps the rendered HTML directly into the DOM with zero handwritten JavaScript.

views/dashboard.rhui 
<!-- Include HTMX and SSE extension -->
<script src="https://unpkg.com/htmx.org@1.9.10"></script>
<script src="https://unpkg.com/htmx.org@1.9.10/dist/ext/sse.js"></script>

<!-- Connect to the SSE endpoint and swap live notifications -->
<div hx-ext="sse" sse-connect="/events">
  <h2 class="text-lg font-bold">Live Activity Feed</h2>

  <div sse-swap="NewNotification" hx-swap="afterbegin" id="feed">
    <p class="text-slate-500">Waiting for incoming activities...</p>
  </div>
</div>
